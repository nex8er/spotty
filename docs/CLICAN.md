Введение
Для работы с командной строкой обычно используется подключение через UART. Подключиться к UART платы, установленной на машине, может быть затруднительно. Для осуществления возможности управления любой платой, подключенной к шине CAN, реализован туннель.

Краткое описание
Суть туннелирования заключается в пересылке всех байтов, которые воспринимаются CLI как вводимые через UART, и выводимых CLI в ответ, в пакетах по сети CAN.

Адресация
Для организации подобного туннеля требуется выделить часть идентификаторов в адресном пространстве CAN. Всего предполагается обслуживать до 447 плат (с номерами узлов от 1 до 447, номер узла 0 зарезервирован). В сети могут располагаться шлюзы, позволяющие осуществлять соединение с платами, находящимися в других сетях CAN. Для каждого узла используются два идентификатора - четный для приема вводимых данных, следующий за ним нечетный - для отправки ответа от узла.
Предложено использовать идентификаторы 400h-77fh. Таким образом, для узла 1 используются идентификаторы 402h (прием команд) и 403h (отправка ответов), для узла N - идентификаторы 400h + N * 2 (адрес приема команд) и 400h + N * 2 + 1 (отправка ответов). Идентификаторы 77eh и 77fh зарезервированы. Идентификатор 400h используется как широковещательный для определения наличия узлов и управления потоком. Идентификатор 701h предлагается использовать для настройки шлюзов.
Далее обсуждается обмен пакетами только с идентификаторами из диапазона 400h..77fh. Обработка пакетов с другими идентификаторами не относится к функциям туннелирования.

Временные характеристики
Любая плата, получившая пакет с идентификатором, соответствующим её номеру узла, должна на некоторое время (5 секунд в текущей реализации) перейти в режим туннелирования, то есть прекратить выдачу в UART своих сообщений, перенаправляя их вместо этого в CAN. При отсутствии в течение 5 секунд пакетов в сети CAN с приемным идентификатором платы режим туннелирования отключается, и плата переходит в обычный режим работы с UART CLI.

Содержание пакетов
Каждый пакет может содержать от 0 до 8 байтов полезной нагрузки. Пакеты, имеющие нулевую длину данных, используются для подключения или поддержания активным подключения.
Широковещательный пакет имеет длину данных 0, используется только для определения наличия узлов в сети (сетях). Имеет идентификатор 400h.
Пакет управления потоком содержит 1 байт данных. Используется для указания узлам приостановить на некоторое время передачу данных. Имеет идентификатор 400h.
Пакет на адрес приема имеет длину данных от 1 до 8. Используется для подключения и для поддержания подключения при наличии данных.
Пакет на адрес приема с длиной данных 0 используется для подключения, поддержания соединения активным при отсутствии передаваемых данных или для определения наличия узла в сети.
Пакет с адреса ответа имеет длину данных 1 до 8 байтов.
Пакет с адреса ответа с длиной данных 0 используется для подтверждения наличия платы или для подтверждения поддержания соединения при отсутствии данных.

Описание работы узлов
Каждый узел, получив пакет со своим приемным идентификатором или с широковещательным идентификатором, должен ответить на него пакетом с идентификатором ответа с нулевой длиной данных.
При получении пакета на адрес приема плата переходит в режим туннелирования, оставаясь там до тех пор, пока в течение 5 секунд на этот адрес не придет ни одного пакета.
В режиме туннелирования данные всех принятых на адрес приема пакетов перекладываются в буфер приема UART, чем имитируется ввод команд пользователем, подключенным через терминал.
Все данные, которые оказываются в буфере отправки UART, не отправляются в UART, а вместо этого отправляются с адреса ответа в пакетах CAN с длиной пакета от 1 до 8 байтов.

Работа шлюза
Шлюз - это любая плата, имеющая выход в две и более сети CAN. В текущей реализации не допускается конфигурация сети с кольцом.
Все принятые пакеты с идентификаторами 400h..77fh, кроме пакетов с номером своего узла, шлюз пересылает во все сети, кроме сети, из которой эти пакеты получены. Возможна настройка шлюза для проброса пакетов с другими идентификаторами.
При заполнении очереди принятых пакетов из некоторой сети выше определенного уровня шлюз отправляет в эту сеть пакет управления потоком. Идентификатор пакета 400h, длина данных - 1 байт. Байт содержит число миллисекунд, на которые требуется приостановить добавление в очередь на отправку пакетов всем участникам сети. Таким образом избегается переполнение очереди принятых пакетов в шлюзе; также даётся возможность отправки пакетов из очереди контроллера CAN для участников сети с низким приоритетом в случае её занятия участниками с более высоким приоритетом.

Управляющие пакеты шлюза - пакеты с идентификатором 401h
Управляющие пакеты шлюза могут быть использованы для определения топологии сети и настройки шлюзов. По умолчанию шлюзы могут быть включены и настроены для проброса любых диапазонов пакетов. В таком случае реализация перечисленных функций не является строго необходимой.
Пакет определения узлов-шлюзов содержит 0 байт данных. Используется для определения узлов, имеющих более одного подключения к шинам CAN. Все такие узлы отвечают пустым пакетом с адреса ответа.
Пакет включения/выключения всех шлюзов содержит 1 байт данных. Нулевое значение означает запрет работы шлюзов, 0xFF разрешает работу. Узел перестаёт выполнять функции шлюза через 1 секунду после получения команды выключения.
Пакет включения/выключения шлюза содержит 4 байта данных. Первые два байта содержат номер узла, которому команда отправляется. Следующий байт - номер сети CAN, к которой имеет отношение команда, или 0xFF, если она имеет отношение ко всем сетям. Последний байт содержит 0 для выключения функций шлюза для выбранных сетей, 0xFF - для включения.
Пакет для определения числа сетей у узла имеет длину данных 2 байта, содержащих номер узла. В ответ на такой пакет узел отправляет пакет данных длиной 3 байта, где первые два байта - номер его узла, а третий байт - количество сетей CAN у него. Пакет для определения наличия узла в сети CAN используется для определения видимости узла из некоторой сети CAN. Пакет состоит из пяти байтов, первые два из которых содержат номер узла, к которому идёт обращение, после чего идут два байта, содержащие номер узла, наличие которого в выбранной сети следует проверить; последним байтом идет номер сети выбранной сети CAN (нумерация идёт с 0). В ответ узел, к которому обращён запрос, высылает 6-байтовый ответ, в котором первые 5 байтов совпадают с байтами пакета запроса, а шестой байт содержит 0, если запрошенный узел не виден из выбранной сети, и 1 - если виден.

Пример обмена
Плата имеет номер узла 5, соответственно, идентификатор для приема - 0x40a, идентификатор для отправки - 0x40b
Клиент: 0x400
Плата: 0x40b
В ответ на широковещательный запрос плата ответила пакетом, подтверждая своё присутствие.
Клиент: 0x40a 0D
Плата: 0x40b 0D
В ответ на адресный запрос с данными плата переходит в режим туннелирования; в ответ посылается пакет с данными, назначенными к выводу на UART.
Плата: 0x40b XX XX XX XX XX XX XX XX
Плата: ...
Плата: 0x40b XX XX XX XX XX XX XX XX
Плата передала текст сообщения частями по 8 байтов. Последнее сообщение может иметь длину менее 8 байтов, но не менее 1 байта.
Для поддержания режима туннелирования клиент регулярно посылает "пустые" пакеты вида:
Клиент: 0x40a
На них плата отвечает:
Плата: 0x40b
В случае, если плата может выдавать сообщения о спонтанных событиях, отправляемые пакеты могут быть не пустыми.
