# AGENTS.md

Контекст для работы над Spotty. Читается в начале каждой сессии — Codex подхватывает этот
файл напрямую, Claude Code через импорт `@AGENTS.md` в `CLAUDE.md`. `CLAUDE.md` теперь
намеренно короткий, чтобы записи не расходились по двум местам, как уже случилось однажды.

## Что это за проект

Модульный терминал-монитор портов. C++20, Qt 6 Widgets, CMake. Версия 0.2.0a.

Плагинов два вида, и оба — настоящие загружаемые модули:
- **транспорты** (`IInterfacePlugin`): `uart`, `loopback`, `jlinkrtt`, `signalgen`;
- **панели и обработка данных** (`IPanelPlugin`): `macros`, `logging`, `search`,
  `generator`, `csvchart`, `filesend`.

`signalgen` — виртуальный источник математических сигналов (синус, косинус, меандр,
треугольник, пила, шум, свип частоты, затухающая синусоида, импульсы, лестница, а также
режимы «все формы разом» и «растущее число колонок»), написанный специально для отладки
`csvchart` без реального устройства. Первая колонка по умолчанию — секунды с открытия
канала, готовая ось X.

Ни одной панели в исполняемом файле не осталось: макросы, журнал, поиск и генератор
загружаются тем же путём, что и сторонние, и ничем не привилегированы. Это и есть проверка
API на прочность — главная цель версии.

## Команды

```bash
# Сборка (macOS; на Linux/Windows убрать CMAKE_PREFIX_PATH или заменить)
cmake -S . -B build -G Ninja -DCMAKE_PREFIX_PATH=/opt/homebrew
cmake --build build

# Запуск с журналом
QT_LOGGING_RULES="spotty.*=true" ./build/spotty.app/Contents/MacOS/spotty

# Проверка второй половины гибридной сборки — делать перед сдачей этапа
cmake -S . -B build-static -G Ninja -DCMAKE_PREFIX_PATH=/opt/homebrew -DSPOTTY_STATIC_PLUGINS=ON
cmake --build build-static

# Тесты: 284 штуки на gtest, два набора — spotty-tests (ядро и SDK, без виджетов)
# и spotty-ui-tests (панельный SDK, под QT_QPA_PLATFORM=offscreen)
cmake -S . -B build -G Ninja -DCMAKE_PREFIX_PATH=/opt/homebrew -DSPOTTY_BUILD_TESTS=ON
cmake --build build && ctest --test-dir build --output-on-failure

# Покрытие: сводка, отчёт в build-cov/coverage/html, порог 80% по строкам
cmake -S . -B build-cov -G Ninja -DCMAKE_PREFIX_PATH=/opt/homebrew \
      -DCMAKE_BUILD_TYPE=Debug -DSPOTTY_BUILD_TESTS=ON -DSPOTTY_ENABLE_COVERAGE=ON
cmake --build build-cov --target coverage

# Распространяемый комплект для текущей платформы
cmake -S . -B build-pkg -G Ninja -DCMAKE_PREFIX_PATH=/opt/homebrew -DSPOTTY_STATIC_PLUGINS=ON
cmake --build build-pkg --target spotty-package   # результат в build-pkg/package/
```

Переводы (нужны `qttools` и `qttranslations`):

```bash
cmake --build build --target update_translations  # lupdate соберёт строки из кода
python3 tools/fill_ru_translations.py             # проставит переводы из словаря
cmake --build build                               # lrelease соберёт .qm в ресурсы
```

Скрипт трогает только непереведённое, поэтому правки из Qt Linguist переживают запуск.
Новые строки он печатает списком — это единственный способ заметить, что в интерфейсе
появился текст без перевода.

Проверка без железа — плагин `loopback`: `loopback0` возвращает отправленное,
`loopback1` выдаёт поток строк с ANSI.

Категории журналирования: `spotty.paths`, `spotty.files`, `spotty.settings`,
`spotty.plugins`, `spotty.plugins.jlinkrtt`, `spotty.registry`, `spotty.session`,
`spotty.icons`, `spotty.history`, `spotty.log`, `spotty.macros`, `spotty.instance`.

## Соглашения по коду

- **Комментарии — на русском, в формате Doxygen** (`\brief`, `\param`, `\return`,
  `\note`, `\warning`). Это явное требование владельца проекта.
- **Строки интерфейса — на английском**, через `tr()`. Английский — исходный язык
  локализации; русский придёт файлом `spotty_ru.ts` на этапе 4. Не путать с комментариями.
- Комментарий объясняет **почему**, а не **что**. Пересказ кода не нужен.
- Стиль оформления кода — Qt: `m_` для полей, `k` для констант в анонимном пространстве
  имён, отступ 4 пробела, ширина 100.

## Правила слоёв

Держат модульность. Нарушение любого — повод остановиться и переделать.

1. **`spotty-core` не линкуется с `Qt6::Widgets`.** Механическая гарантия
   проверяемости логики без `QApplication`. Это правило безусловное.
2. **Никакой плагин не линкуется со `spotty-core`.** Не хватает чего-то плагину —
   добавлять в публичный SDK (`include/spotty/api`, `include/spotty/data`,
   `include/spotty/ui`), а не открывать ему ядро.
3. **Плагин интерфейса линкуется только со `Spotty::Api` и виджетов не создаёт.**
   Возвращает `SettingsSchema`, диалог строит ядро. Транспорт живёт в отдельном потоке,
   и виджеты ему не только не нужны, но и запрещены.
4. **Плагин панели линкуется со `Spotty::UiApi` и виджеты создаёт.** Это его работа:
   график, таблица, форма. Всё, что ему даёт приложение, приходит через `IPanelHost` —
   ни `Session`, ни `SettingsStore`, ни `TerminalView` он не видит.

Правила 3 и 4 — не послабление, а разделение. Прежняя формулировка («плагины не создают
виджеты») относилась к единственному существовавшему виду плагинов. Когда появился второй,
она стала запрещать то, ради чего он заведён, и была переформулирована; правило 1, на
котором держатся тесты, при этом не тронуто.

**Виды плагинов различаются `KIND` в `spotty_add_plugin()`** (`INTERFACE` по умолчанию,
`PANEL`) и своим IID. У них независимые версии ABI: `SPOTTY_API_VERSION` и
`SPOTTY_UI_API_VERSION`. Связаны они `static_assert` в `UiApiVersion.h` — поднять основную,
не заметив панельную, нельзя.

## Ловушки, на которые уже наступали

**Обе библиотеки SDK обязаны быть одного вида.** `spotty-api` и `spotty-ui-api`
порождаются из одной опции `SPOTTY_STATIC_PLUGINS`, поэтому разойтись не могут — но если
однажды кто-то сделает их независимыми, разделяемая `Spotty::Api` со статической
`Spotty::UiApi` даст плагину собственную копию метаобъектов `PanelWidget` и `IPanelHost`,
после чего `connect()` и `qobject_cast()` молча перестанут работать. Проверка стоит в
`src/uiapi/CMakeLists.txt` и падает на этапе конфигурации: ошибка сборки лучше, чем
панель, которая загрузилась и не получает данных.

**Параметр конструктора `host` перекрывает метод `host()`.** У `PanelWidget` есть и то и
другое, и внутри тела конструктора панели неквалифицированное `host()` разрешается в
параметр — получается «вызов объекта, не являющегося функцией». Диагностика компилятора при
этом указывает на лямбду, а не на причину. Во всех панелях параметр назван `panelHost`.

**Порядок фаз загрузки плагинов значим.** `PluginManager::load()` обходит каталоги,
`PanelPluginRegistry::load()` разбирает панельную роль, и только затем
`PluginManager::finishLoading()` заносит в `failures()` всё нераспознанное. Вызвать
`finishLoading()` раньше — значит объявить отказом каждый панельный плагин. «Распознан» при
этом означает «роль признана», а не «проверки пройдены»: плагин, отвергнутый по версии,
уже дал свою запись, и вторая, менее внятная, ему не нужна.

**SDK обязан быть разделяемой библиотекой.** `IInterfaceChannel` — класс с `Q_OBJECT`, а
Qt сопоставляет сигналы, сравнивая **указатели** на `QMetaObject`. Отдельная копия
`staticMetaObject` в приложении и в плагине приводит к тому, что `connect()` молча не
срабатывает: ни ошибки сборки, ни предупреждения, просто не приходят данные. Подробности —
в `include/spotty/api/SpottyApiExport.h`. Не превращать `spotty-api` обратно в
`INTERFACE`-библиотеку.

**Подстановка цветов в QSS идёт от длинных плейсхолдеров к коротким.** Иначе `@text`
затирает начало `@textMuted`. Проверка на оставшиеся `@имя` уже встроена в
`ThemeManager::resolveStylesheet()`. Через тот же механизм подставляются размеры из
`ThemeMetrics` (`@radius`, `@padV`, `@fontSmall`) — сразу с единицей измерения, поэтому
`@radiuspx` писать не нужно и нельзя.

**`min-width` и `min-height` в QSS — размеры содержимого, а не всего элемента.** Отступы и
рамка прибавляются сверху. `min-height: 28px` рядом с `padding: 5px 12px` даёт кнопку
высотой 40 px, а не 28. Значения в `ThemeMetrics` заданы именно как содержимое, и там же
стоит формула полной высоты.

**Fusion выводит цвет обводки флажка из `QPalette::Window`, затемняя её.** На тёмной теме
затемнять нечего, и квадратик становится невидимым: снятый флажок неотличим от пустого
места, поставленный выглядит галочкой в воздухе. Палитрой это не чинится — цвет считается
от фона окна, а не берётся из роли. Поэтому `QCheckBox::indicator` — единственный
подэлемент, отрисовку которого таблица стилей перехватывает; галочку приходится подставлять
изображением (`:/icons/check.svg`), потому что собственный фон подэлемента отменяет родную
отрисовку целиком, вместе с самой галочкой.

**Взяв подэлемент под свой стиль, изображение обязан дать сам.** Любое собственное правило
для `::drop-down`, `::up-button`, `::down-button` или `::indicator` отменяет родную
отрисовку **целиком**, вместе со стрелкой или галочкой внутри. Полумеры тут нет: либо
подэлемент не трогают вовсе, либо задают и фон, и `image: url(...)`. На тёмной теме
забытая стрелка не бросается в глаза при беглом взгляде — счётчик просто выглядит как две
пустые рамки. Стрелки лежат в `resources/icons/chevron-*.svg`, цвет один на обе темы:
нейтрально-серый проходит по контрасту и на тёмном фоне поля, и на белом, а иначе на каждую
тему понадобился бы свой файл.

**Собственная рамка у `QComboBox` переводит раскрытый список в «менюшный» режим, и
бороться надо с режимом, а не с его следствиями.** `QStyleSheetStyle` начинает отвечать на
`SH_ComboBox_Popup` утвердительно, и `QComboBoxPrivate::showPopup()` строит список как
меню: раздвигает окно на `PM_MenuVMargin` сверху и снизу (эти пиксели никто не
закрашивает, и они читаются как чужая тёмная рамка), заменяет полосу прокрутки
стрелками-скроллерами и — главное — считает высоту окна **без** тех самых полей. Список из
трёх пунктов показывал два с половиной и стрелку.

Два захода на следствия провалились: поля не отменить (берутся из стиля до появления
окна), высоту не подогнать надёжно (`showPopup()` ставит геометрию сам, уже после
обработчика показа). Причина снимается одной строкой — `FusionStyle` в `ThemeManager.cpp`
возвращает `SH_ComboBox_Popup` нулём. Дальше всё штатно: окно под полем, высота по
`maxVisibleItems` (у нас 12, ставится на `QEvent::Polish` — позже поздно), прокрутка только
при переполнении. Не возвращать «менюшный» режим и не давать `QComboBox` обходных рамок.

Рамку раскрытого списка рисует **вид**, а не окно-контейнер: контейнер кладёт вид без
полей, и собственная рамка контейнера оказывается закрыта целиком. Само окно
(`QComboBoxPrivateContainer`) из таблицы стилей недостижимо — селектор с именем приватного
класса не срабатывает, проверено; фон ему ставит палитрой
`ThemeManager::applyComboPopupLook()`.

**`qWarning()` из оконного приложения на Windows в stderr не попадает.** Сборка идёт с
`-mwindows`, консоли нет, и Qt уводит вывод в отладчик через `OutputDebugString` — файл с
перенаправленным stderr остаётся пустым, и отладочная печать выглядит так, будто код не
выполняется. Лечится переменной окружения `QT_FORCE_STDERR_LOGGING=1`.

**Редактор в ячейке таблицы стилизуется отдельно от прочих полей.** Общие `min-height` и
отступы делают его выше строки, а Qt не сжимает редактор до размера ячейки — он растягивает
**строку**, и таблица дёргается при вводе. Правила `QAbstractItemView QLineEdit` и соседние
снимают наименьшие размеры и скругление.

**`QApplication::setFont()` вызывать после `setStyle()`.** `setStyle()` заново «полирует»
виджеты и возвращает им шрифт стиля, затирая установленный раньше. В `ThemeManager::apply()`
порядок именно такой.

**Кегль интерфейса в QSS не задавать.** Правило вида `QWidget { font-size: 13px; }`
переопределяет системный шрифт и заодно отменяет системную настройку размера текста —
интерфейс перестаёт увеличиваться вместе с остальной системой. Кегль ставится один раз
через `QApplication::setFont()`; в таблице стилей от него отсчитываются только заголовок
панели и подпись (`@fontTitle`, `@fontSmall`).

**`InterfaceDescriptor::id` строится из VID/PID/серийного номера, а не из имени
устройства.** Узел `/dev` переназначается при переподключении, и настройки пользователя
теряются. Это самая коварная ошибка в API — предупреждение стоит в заголовке.

**Отметку времени в `dataReceived()` ставить в момент чтения, монотонными часами.** Из неё
считаются межбайтовые паузы для пакетизации.

**`enumerate()` вызывается раз в секунду в потоке интерфейса.** Держать дешёвым.

**В Qt 6 у `QSerialPort` больше нет `FramingError`, `ParityError` и `BreakConditionError`** —
они удалены, и ошибки кадрирования, чётности и переполнения приходят общим `ReadError`.
Различить их средствами Qt нельзя, остаётся текст из `errorString()`.

**`TextStyle` хранит цвет как `quint32`, а не `QRgb`.** `QRgb` объявлен в QtGui, с которым
ядро не линкуется. Распаковкой занимается `AnsiPalette` в слое UI.

**Строка в `TerminalBuffer` создаётся лениво, при первой записи текста.** Иначе отрезок из
одних управляющих последовательностей (а устройства сплошь и рядом шлют
`"текст\r\n\033[0m"`) добавлял бы пустую строку после каждой осмысленной.

**Отложенный пересчёт обязан вызываться отовсюду, откуда меняется его исходное.** Метки на
полосе прокрутки считаются по таймеру — обход буфера на сотни тысяч строк дорог. Пуск
таймера стоял в одном лишь `updateScrollBars()`, то есть срабатывал при поступлении строк;
смена образца поиска и правка правил подсветки его не поднимали. На живом потоке это
незаметно — строки идут, метки обновляются сами; на остановленном выводе, где ищут чаще
всего, меток не появлялось вовсе. Пуск вынесен в `scheduleMarkerUpdate()` и зовётся из всех
трёх мест. Такую же проверку стоит делать для любого расчёта, который отложили ради цены:
дёшево не значит редко.

**`hide()`, поставленный ребёнку, показ родителя не отменяет.** Строка выбора второго
интерфейса пряталась явным `hide()` при построении, а режим «два интерфейса» показывал её
карточку. Ребёнок оставался скрытым, и на экране появлялась пустая полоска. Скрытость
ребёнка — его собственное состояние, а не следствие родительского.

**Вставка нескольких виджетов по одному индексу переворачивает их порядок.** Кнопки полосы
плагина вставлялись `insertWidget(indexOf(m_modeCombo) + 1, …)` в цикле, и объявленный
плагином порядок «пауза, очистка» превращался в «очистка, пауза». Позиция считается один
раз и растёт с каждой вставкой.

**Служебная метка системной строки — деталь представления, а не текста.** Текст из
`TerminalBuffer::appendSystemMessage()` хранится без `*`, поэтому копирование отдаёт
только сообщение. `TerminalView::directionMark()` рисует `* ` в той же колонке, где для
данных находятся `> ` и `< `. У системных строк есть `StyleRun::italic`, но отдельная
ветка отрисовки системных строк обходит общий цикл стилей: курсив в ней нужно ставить
явно, иначе флаг в буфере никак не влияет на экран.

**Источник строки принадлежит сессии, а не общему буферу.** В режиме двух интерфейсов
`Session::setSharedBuffer()` раньше вызывал `TerminalBuffer::setSource()`: вторая сессия
перезаписывала общую метку, и все строки показывались как `B:`. Источник передаётся в
`append()` и `appendSystemMessage()` каждой сессией отдельно; смена источника завершает
незаконченную строку, чтобы данные A и B не слипались. Локальное эхо применяется к обеим
сессиям — отключать его у B «ради чистоты» нельзя, его уже отличает `B:`.

**История терминала не очищается при смене интерфейса и режима области вывода.** Смена
порта добавляет системные границы закрытия и открытия, но не вызывает `clear()`: прошлые
данные нужны для сравнения. При включении двух интерфейсов общим становится собственный
буфер A, а не новый пустой `m_sharedBuffer`; поэтому история A не исчезает и B дописывает
к ней свои строки. Очищать вывод имеет право только явное действие пользователя.

**Отсчёт номеров строк — состояние представления.** По умолчанию `m_lineNumberOrigin`
равен `-1`, поэтому первая строка видна как `1`. Пункт ПКМ «Set line number origin here»
назначает нулём строку под курсором: до неё номера отрицательны, после — положительны.
Ширина колонки считается по обоим крайним относительным номерам, включая знак минуса;
иначе текст терминала сдвигался бы при установке точки отсчёта.

**Горизонтальная полоса прокрутки терминала мигала и дёргала весь вывод.** Ширина
содержимого меряется по видимому окну (обходить сотни тысяч строк на каждой перерисовке
нельзя), и менялась она при каждой прокрутке. Полоса то появлялась, то исчезала, viewport
на её высоту сжимался и разжимался, и текст прыгал по вертикали — тем сильнее, чем быстрее
шли данные. Диапазон теперь только растёт и сбрасывается вместе с буфером.

**`setBackground()` у ячейки таблицы не работает, пока действует `QTableView::item`.**
Правило из таблицы стилей задаёт фон само и отменяет выставленное моделью — цвет правила
подсветки не показывался вовсе. Та же ловушка, что с флажком: взяв элемент под свой стиль,
изображение обязан дать сам. Цвет рисуется значком, значение хранится в `Qt::UserRole`.

**Полупрозрачность в QSS задаётся только через `rgba()`.** `QColor::name()` отдаёт
`#rrggbb` без альфы, а `#aarrggbb` разборщик QSS не понимает. Для таких мест в
`resolveStylesheet()` заведены отдельные плейсхолдеры.

**Прокрутка колесом над `QComboBox` гасится явно.** Иначе случайный скролл над окном молча
переключает активный порт — закрывает текущий и открывает чужой.

Владелец подключается позже, и начальное состояние пропадает. Так уже произошло с
правилами подсветки в `SearchPanel`: они загружались, но до терминала не доходили.
Решение — геттер (`SearchPanel::highlightRules()`), который `MainWindow` вызывает после
связывания.

**`applySettings()` глушит сигналы кнопок через `QSignalBlocker`.** Иначе установка
состояния кнопки поднимает её обработчик, который тут же перезаписывает настройку
значением кнопки — и применение настроек отменяет само себя.

**Ноль — законная отметка монотонных часов, а не признак «данных не было».** В
`Packetizer` ноль использовался как сентинел, и первая же порция, пришедшая сразу после
`QElapsedTimer::start()`, навсегда отключала разбиение по паузе. Признак теперь отдельный
булев. Тот же приём с «магическим» значением стоит искать и в остальном коде.

**Пакет из одних управляющих байтов должен создавать строку.** Разборщик такие байты
отбрасывает, текста не появляется, и при ленивом создании строки двоичная посылка
исчезала из вывода целиком — вместе с исходными байтами, то есть и из HEX-режима.

**На macOS arm64 подпись обязательна.** `macdeployqt` переписывает пути внутри
скопированных `.dylib` и ломает их подписи; система убивает такой процесс сигналом KILL
ещё до `main()`, ничего не сообщая. В `SpottyPackaging.cmake` шаги разделены: развернуть,
подписать заново (`codesign --force --deep --sign -`), затем собрать образ.

**Проверить клик на этой машине нельзя**

**Все ключи настроек живут в `AppSettings`, и только там.** До этого они были константами
в четырёх файлах и уже начали расходиться. Опечатку в строке ключа не поймает ни
компилятор, ни тесты: настройка просто перестаёт сохраняться. Добавление настройки — поле
в структуре плюс строка в `MainWindow::applySettings()`.

**Панель, читающая настройки в конструкторе, не может сообщить о них сигналом.** — у терминала нет доступа к Accessibility,
`osascript` с `keystroke` молча не работает. Всё, что требует нажатия (кнопка записи лога,
горячие клавиши макросов, drag-and-drop), проверяется только пользователем. Обходной
путь для остального — задать состояние через `settings.json` и перезапустить.

**Не удалять виджет из обработчика его же сигнала.** `InterfaceSettingsPanel` пишет правку
в `InterfaceRegistry` прямо из `editingFinished`/`toggled`/`editTextChanged` редактора;
запись поднимает `registry->changed()` синхронно, а он подключён к перестроению того же
диалога — которое удаляет старые виджеты полей, включая тот, чей обработчик ещё выполняется.
Результат — `EXC_BAD_ACCESS` при первом же наборе текста в поле. Решение в три слоя: флаг
`m_populating` вокруг каждой записи в реестр (гасит перестроение, вызванное собственной же
правкой), `deleteLater()` вместо `delete` при пересборке полей (не ломается, даже если
где-то забудут про флаг), и сам факт, что оба нужны одновременно — обычный сигнал/слот
внутри Qt для такого не защита.

**`#pragma pack(1)` для FFI-структуры с указателями — не безопасное умолчание, а решение,
которое нужно доказывать для каждой структуры отдельно.** В `JlinkArmLibrary` несколько
структур SEGGER SDK объявлены вручную (заголовка от SEGGER в поставке нет). Две из них —
только `quint32`/массивы байт — совпадают что с `pack(1)`, что с обычным выравниванием, и
по инерции третью (`JLINK_DEVICE_INFO`, вперемешку `quint32` и 8-байтовые `const char*`)
занесли в тот же блок `pack(1)`. Обычное выравнивание вставляет отступ перед указателем,
`pack(1)` — нет: поле `sName` съезжает на 4 байта, оттуда читается не указатель, а чужие
байты, и `JLINK_DEVICE_GetInfo()` роняет процесс на первом же вызове. Раскладка каждой
такой структуры проверена не по памяти, а отдельной программой на `dlopen()`/`dlsym()` в
обход Spotty (упасть в ней безопасно) со сверкой результата по паспортным данным реального
чипа — адрес и размер флеша, RAM, производитель. Так же стоит проверять любую новую
структуру этого рода, а не копировать соседний `#pragma pack` не глядя.

**`TerminalBuffer::clear()` не сбрасывает сквозную нумерацию строк — обращаться к строкам
после неё нужно через `firstLineNumber()`, а не через ноль.** Нумерация продолжается
намеренно (сохранённая где-то позиция обязана указывать на ту же строку и после очистки),
но тест на общий буфер вызывал `shared.clear()` уже после того, как в буфер попали две
строки «открыт» (по одной на сессию), и затем читал `shared.line(0)`/`line(1)`, как будто
нумерация обнулилась. `line(0)` целился в уже вытесненную строку, `line()` вернул `nullptr`,
и `->source` уронил процесс — SEGFAULT на macOS/Linux, `0xc0000005` на Windows, на всех
платформах CI сразу. Чинится взятием `base = shared.firstLineNumber()` сразу после
`clear()` и индексацией от него.

**`QLocalServer::listen()` на Windows не проваливается, если имя уже занято чужим
сервером.** Задокументировано самим Qt: два сервера могут слушать один и тот же pipe
одновременно, и новые подключения достаются то одному, то другому. `SingleInstanceGuard`
опирался именно на провал `listen()`, чтобы отличить второй запуск от первого — работало на
Unix и молча впускало бы второй экземпляр на Windows. Правильная проверка — сперва
подключиться к имени клиентом (`QLocalSocket::connectToServer()`), и только если никто не
ответил, поднимать сервер. Уборка осиротевшего сокета после аварийного завершения (сама
`listen()` там честно проваливается) остаётся отдельным, более редким случаем —
Unix-специфичным по факту, а не по коду.

## Ключевые решения и их причины

| Решение | Почему |
|---|---|
| Два SDK, а не один | Граница проходит по `Qt6::Widgets`. Транспорту виджеты не нужны и вредны — он живёт в отдельном потоке; панели без них не существует. Один SDK на оба вида означал бы Widgets в зависимостях UART |
| Отдельная `SPOTTY_UI_API_VERSION` | Общая заставила бы `PluginManager` отвергать UART при правке панельного контракта — с причиной, к которой транспорт непричастен |
| Две фазы загрузки вместо базового `IPlugin` | Общий базовый класс сломал бы IID и ABI существующего SDK ради экономии четырёх строк на плагин. Дубликаты в отчёте решаются тем, что каталоги обходятся один раз, а не наследованием |
| `IPanelHost` вместо `AppContext` | Панель не должна видеть `Session` и `SettingsStore`: половина их возможностей ей не нужна, а вреда наделать позволяет. Заодно это единственный способ дать ей что-то, не открывая `spotty-core` |
| Цвета хосту — перечислением, не структурой | Структура заморозила бы раскладку в ABI: добавление цвета в тему ломало бы уже собранные панели |
| Qt Widgets, не QML | Полный контроль над отрисовкой терминала; `qtdeclarative` не установлен |
| Ядро мультисессионное, UI односессионный | Вкладки добавятся позже без переписывания ядра |
| Гибрид плагинов MODULE + STATIC | Динамика для разработки, статика для релизов и подписи macOS |
| ANSI: SGR + управление строкой | Покрывает вывод прошивок и bootloader'ов; полный VT100 не окупается |
| Fusion + своя палитра, не нативный стиль | Единый вид на всех ОС; тёмная тема иначе ведёт себя всюду по-разному |
| Цвета общие, размеры платформенные (`ThemeMetrics`) | Единый цвет — это выбор; единый кегль — нет. Системный шрифт Windows 9–10 pt против 13 pt в macOS, разное скругление и ширина полос прокрутки: одно число на обе системы выглядит чужим на одной из них |
| Заливка акцентом только у кнопки по умолчанию | Единственное отступление от монохромности. В полосе отправки рядом стоят поле, два списка и кнопка; без выделения главного действия его приходится искать заново каждый раз. Обе системы оформляют кнопку по умолчанию так же |
| JSON + переносной режим, не QSettings | Читаемо, правится руками, переносится между ОС |
| Свой `TerminalView`, не `QPlainTextEdit` | Нужны колонка времени, метка TX/RX, HEX, фильтр, буфер в сотни тысяч строк |
| `loopback` написан раньше UART | Доказывает, что API не «UART-образный»; позволяет разрабатывать UI без железа |

Отклонения от исходного плана: убран `defaultSettings()` из `IInterfacePlugin`
(умолчания живут в схеме, два места разошлись бы), добавлен `settingsSummary()`
(ядро не может знать, что «115200 8-N-1» — это то, что нужно показать в списке).

Наборов два. `spotty-tests` покрывает `spotty-core` и `spotty-api` и не линкуется с
Qt6::Widgets — именно на этом держится гарантия, что вся логика проверяема без
`QApplication`. `spotty-ui-tests` покрывает панельный SDK, линкуется с виджетами и в
подсчёт покрытия не входит: там мерялась бы доля покрытого кода интерфейса, а он
проверяется запуском.

Фреймворк тестов — GoogleTest, не Qt Test: выбрано владельцем проекта. Подключается через
FetchContent с закреплённой версией (`SPOTTY_GTEST_TAG`), при наличии системного пакета
используется он. Тесты покрывают `spotty-core` — он не линкуется с Widgets именно ради
этого, и весь набор гоняется без графической подсистемы.

Покрытие: 82.3% по строкам, порог 80% (`SPOTTY_COVERAGE_MINIMUM`), цель `coverage` падает
при нарушении. Меряются `spotty-core` и `spotty-api` — вся логика, не зависящая от
виджетов. Сборка с покрытием форсит `SPOTTY_STATIC_PLUGINS=ON`: счётчики в разделяемой
библиотеке ведут свой набор данных, и сводка по бинарнику тестов их не видит. Отчёт о покрытии — рабочий инструмент, а не
украшение: именно он показал, что `Session.cpp`, центральный класс ядра, не покрыт
вообще, хотя набор тестов выглядел полным.

## Известные мелочи

- Заголовок окна под тему красит `spotty::PlatformChrome` (`DwmSetWindowAttribute` на
  Windows, `NSWindow.appearance` на macOS). Проверено на Windows; вариант для macOS собран
  не был — на этой машине нет ни компилятора Objective-C, ни AppKit.
- Период отправки макроса 1 мс недостижим точно — гранулярность таймеров ОС 1–15 мс.
  Решено показывать фактически достигнутый интервал для периодов меньше 10 мс.
- `qttools` (`lupdate`/`lrelease`) не установлен. Нужен на этапе 4; CMake его отсутствие
  переживает.
- Изменения оформляются отдельными локальными коммитами по запросу владельца.
